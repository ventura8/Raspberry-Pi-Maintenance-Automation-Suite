# v1.1.7: Close the sudo-install staging race in the root-owned tree

## Summary

v1.1.5 moved the suite into the root-owned `/usr/local/lib/pi-maintenance` so that user-session
malware could not rewrite what root cron executes. The installer still staged every download in a
user-owned `mktemp` file under `/tmp` and then ran `sudo install` on it. Any process running as
the installing user could swap that file's contents between the download and the privileged copy,
and root cron would then run the payload. This affected fresh installs, the manager's
"Force Update Scripts", and `install.sh --update` run from a user shell. Self-update from root
cron was not affected. This release removes the user-writable staging step. It also moves the
Fedora CI lane to `fedora:46`.

## What Changed

### 1. Security: downloads never pass through a user-writable file

- `_install_atomic_curl` streams `curl | sed` (the `RECIPIENT_EMAIL` rewrite) straight into the
  privileged `install /dev/stdin`, which writes a staging file inside the destination directory.
  The staged file only replaces the live script when the whole pipeline succeeded, including
  `curl`, so a failed or partial download never goes live.
- Local-checkout libraries and `.version` go through the same privileged `install`
  (`_install_atomic_mv`, which now takes trusted input only: the checkout or `/dev/stdin`).
- `_install_tmp` and `_install_atomic_copy` are removed; nothing stages under `${TMPDIR:-/tmp}`
  any more.

### 2. CI: Fedora lane moves to `fedora:46`

- Taken over from Dependabot PR #16, which only changed the `FROM` line. The Dockerfile is renamed
  to `fedora-46.Dockerfile` (lane files are named after the image tag), and the dnf pins that
  do not exist on 46 are refreshed (`ca-certificates`, `curl`, `glibc-langpack-en`, `procps-ng`, `python3-pip`).
- `fedora:46` is currently Rawhide (several pins are release candidates), so expect this lane's
  pins to need refreshing more often until Fedora 46 is released.

### 3. Tests and docs

- New `tests/install_root_owned.bats` cases: downloads into a root-owned tree never use
  `curl -o` or the user's `TMPDIR` and leave no staging files behind; a failed download keeps the
  previously installed script.
- The `component_tests.bats` curl mock now also serves stdout downloads.
- `AGENTS.md`, `Instructions.md`, `docs/script_logic.md`, `.github/copilot-instructions.md`,
  `.github/instructions/shell-scripts.instructions.md`, and the installer-tester and
  distro-matrix-tester skills document the "privileged process writes the bytes" rule and the
  new lane.

## Validation

- `./scripts/build-and-test.sh --full` passed with the security fix: Docker lint, the coverage
  gate on `debian:trixie`, and compat + e2e on every distro lane.
- `./scripts/build-and-test.sh --lints-only` and `--distro fedora:46` passed after the lane move.

## Breaking Changes

- None for installed hosts. Contributors: the Fedora lane is now `fedora:46`.

## Notes

- Existing hosts get the fixed installer on the weekly `update_self.sh` run. That run is from root
  cron and was never exposed, but interactive "Force Update Scripts" and user-shell `--update`
  runs after upgrading use the new path.
- Residual scope: `curl` itself still runs as the invoking user. On hosts that allow same-user
  `ptrace` (`kernel.yama.ptrace_scope=0`), malware could tamper with that process, but it could
  equally hijack the sudo-authenticated installer shell, so this is outside the installer's reach.
