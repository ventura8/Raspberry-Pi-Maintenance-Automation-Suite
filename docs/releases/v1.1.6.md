# v1.1.6: SonarQube Cloud gate, HTTPS-only downloads, and a lint gate that actually runs

## Summary

This release adds SonarQube Cloud static analysis and fixes what it found. Along the way it
turned up real problems: a firmware download that a redirect could downgrade to plain HTTP,
local SMTP credentials that could be baked into Docker test images, and a lint step that had
never actually run. The step was hadolint, which AGENTS.md lists as a quality gate: its file
pattern matched no Dockerfile, and the gate skipped it silently. All three are fixed. There
are no behaviour changes for installed hosts beyond the hardening described below.

## What Changed

### 1. Security hardening in shipped scripts

- `update_samsung_ssd.sh`: both downloads now refuse plain HTTP, including across `-L`
  redirects (`--proto '=https' --proto-redir '=https'`, shared through one
  `CURL_HTTPS_ONLY` array). The firmware ISO matters most: it is extracted and its
  `fumagician` payload is run via `sudo`, so a downgraded redirect could have let a network
  attacker replace it.
- `update_self.sh`: the GitHub Releases API request is HTTPS-only in the same way.

### 2. SonarQube Cloud

- `sonar-project.properties` for org `ventura8`. Automatic Analysis scans every push and PR
  with no secret. A `sonarqube` CI job is included but skips unless `SONAR_TOKEN` is set,
  because Sonar rejects CI analysis while Automatic Analysis is on.
- The first analysis reported 541 findings. All are fixed except a few documented false positives. The largest groups:
  - 364 single-bracket `[ ]` tests converted to `[[ ]]`.
  - 117 explicit `return` statements added. A bare `return` keeps the last command's status,
    so this changes no behaviour; `return 0` would have hidden failures.
  - Default `*)` branches on `case` statements.
  - Positional parameters assigned to named locals.
  - Uppercase locals renamed to lower_case.
  - Repeated string literals extracted into constants.
- The `[[ ]]` conversion also fixed a latent bug: `"$2" == -*` now matches as a pattern
  instead of undergoing pathname expansion.
- A handful of documented false positives stay open, for example a deliberate
  `local PATH="$1"` scoping idiom and a `local -n` out-parameter.

### 3. Lint gate and Docker images

- **Bug fix:** `tests/lint.sh` collected Dockerfiles with `git ls-files "Dockerfile*"`,
  which matched nothing, so hadolint and the Dockerfile line-length check never ran. The
  pattern is now `"*Dockerfile*"`, and both checks now gate the build.
- Enabling hadolint surfaced findings, all fixed without ignore directives:
  - apt packages are version-pinned (`'curl=8.14.1*'`) and dnf packages likewise
    (`curl-8.21.0`).
  - Arch starts from a dated `archlinux:base` snapshot, then runs `pacman -Syu`, so the lane
    still tests current rolling Arch.
  - Images switch to a numeric `USER ${CI_UID}`.
- Test images copy only the files the suite needs instead of `COPY . .`, and leave them
  root-owned.
- `.dockerignore` now excludes `ssmtp.conf`, `.env`, `*.pem` and `*.key`. `.gitignore`
  already excluded `ssmtp.conf` as holding passwords, but the Docker build context did not.
- Mail configs in the test images are owned by the test user's numeric uid and gid at
  `0660`, replacing world-writable `0666`.
- The lint tools are hadolint v2.15.1 and actionlint 1.7.12. Both are fetched with
  `ADD --checksum` using the publishers' own release checksums.

### 4. Dependencies and CI

- The Fedora lane moves from `fedora:44` to `fedora:45`. `fedora:46` is Rawhide, not a release.
- `ci.yml` actions are pinned by commit SHA (as `release.yml` already was).
- `sonarqube-scan-action` is v8.2.2, and `lizard` is pinned to 1.24.0 with `--only-binary :all:`.

### 5. Tests and docs

- Fixed the curl test mock: it took `=https` as the URL, so the Samsung and GitHub response
  branches were silently skipped while tests still passed.
- New "Docker Image Pinning" section in `AGENTS.md`, with the procedure for refreshing pins.
- `Instructions.md`, `docs/development_standards.md`, the distro-matrix-tester skill and the
  `README.md` badge are updated.

## Validation

- `./scripts/build-and-test.sh --full` passed. Lint ran in Docker, with hadolint checking all
  seven Dockerfiles. Coverage was 91.74% overall and every file was at least 90%. All five
  distro lanes passed both compat and e2e.
- 226/226 BATS tests pass, and the SonarQube Cloud quality gate passes with 0 new issues.

## Breaking Changes

- None for installed hosts. Contributors: every Dockerfile package is now version-pinned. A lane
  that fails with `E: Version '…' was not found` (apt) or `No match for argument` (dnf) has a
  stale pin; refresh it as described in `AGENTS.md` → "Docker Image Pinning".

## Notes

- Existing hosts get the hardened scripts on the weekly `update_self.sh` run.
