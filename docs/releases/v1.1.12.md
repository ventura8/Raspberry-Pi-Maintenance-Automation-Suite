# v1.1.12: Refuse untrusted sibling lib/ and cwd uninstall before sudo

## Summary

A security scan found that the piped installer still treated the current working directory as
its sibling tree when `BASH_SOURCE` was empty. Same-UID malware that planted `$HOME/lib/os_pkg.sh`
(or `$HOME/uninstall.sh`) could hijack `pkg_install` / the manager Uninstall option and run as
root on the victim's next `curl|bash`, Force Update, or self-update. This release closes those
paths.

## What Changed

### 1. Piped installer has no sibling tree

- Empty, `/dev/*`, or `/proc/*` `BASH_SOURCE` leaves `_INSTALL_ROOT` empty. `curl|bash` and
  process substitution no longer resolve `dirname` to `$PWD`.
- Parse-time lib sourcing and the `ui_msg.sh` fallback require `_install_src_trusted` before
  any on-disk `source`. User-owned checkouts and `mktemp` staging trees are skipped when the
  install target needs root; helpers then come from `$INSTALL_DIR/lib` or `_fetch_bootstrap_libs`.

### 2. Self-update staging no longer ships lib/

- `update_self.sh` stages only tagged `install.sh` and `VERSION`. The user-owned staging
  directory never receives `lib/`, so `--update` sources the root-owned `$INSTALL_DIR/lib` (or
  fetches via the exported `$RAW_URL`).

### 3. Uninstall ignores cwd

- Manager Uninstall runs a trusted `$_INSTALL_ROOT/uninstall.sh` only, otherwise
  `curl …/uninstall.sh | bash`. A planted `./uninstall.sh` in `$HOME` is never executed.
- Piped `uninstall.sh` itself leaves `_RPI_UNINSTALL_ROOT` empty on empty/`/dev`/`/proc`
  `BASH_SOURCE`, so a planted `$PWD/lib/ui_msg.sh` cannot wrap `sudo` before crontab cleanup.

### 4. Tests and docs

- New BATS coverage for piped planted `lib/os_pkg.sh`, user-owned staged lib with a root-owned
  install tree, and cwd uninstall plants.
- `AGENTS.md`, `docs/script_logic.md`, `Instructions.md`, and installer/self-update skills
  document the trust rules.

## Upgrade Notes

No action is needed. Existing installs pick this up through the weekly `update_self.sh` run.
After that update, a subsequent self-update uses the new staging layout automatically.
