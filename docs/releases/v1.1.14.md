# v1.1.14: Block shell injection via the mail user into root-cron scripts

## Summary

A security report showed that `download_scripts` copied the msmtp `user` (or ssmtp `AuthUser`) field
straight into a `sed` replacement that rewrites `RECIPIENT_EMAIL="..."` in every maintenance script
under `/usr/local/lib/pi-maintenance`. The value was neither validated nor escaped, and `MSMTP_CONF` /
`SSMTP_CONF` were read from the environment. Same-UID malware could export `MSMTP_CONF` pointing at a
crafted file whose user field contained `";<cmd>;RECIPIENT_EMAIL="`, wait for the user to run
**Force Update Scripts** or `install.sh --update`, and get arbitrary commands executed as root by cron.

This release validates and escapes the injected address, ignores mail config path overrides outside
`TEST_MODE`, and refreshes the CI dependency pins.

## What Changed

### 1. RECIPIENT_EMAIL injection hardening (`install.sh`)

- `download_scripts` only injects a mail user that passes `validate_email_address`; anything else
  keeps the shipped `your_email@gmail.com` placeholder and prints a warning.
- New `_recipient_email_sed_expr` / `_sed_replacement_escape` helpers build the `sed` expression:
  they refuse invalid addresses and escape `\`, `/` and `&`. Both `_install_atomic_curl` and
  `save_email_configuration` use them, so the sink itself fails closed.
- `save_email_configuration` rejects invalid addresses before writing mail config, cron `MAILTO`,
  or rewriting installed scripts (covers the non-interactive matrix install path too).
- `MSMTP_CONF`, `SSMTP_CONF` and `REVALIASES` environment overrides are honoured only when
  `TEST_MODE=true`; otherwise `install.sh` uses `/etc/msmtprc`, `/etc/ssmtp/ssmtp.conf` and
  `/etc/ssmtp/revaliases`.

### 2. Regression tests

- `tests/install_extended.bats`: an injecting msmtp user is refused (placeholder kept, payload never
  written or run), a valid user is injected verbatim, `_install_atomic_curl` and
  `save_email_configuration` reject invalid addresses, sed specials are escaped, and env path
  overrides are ignored outside `TEST_MODE`.

### 3. Dependency updates

- Arch test image: `archlinux:base-20261025.0.616225` (supersedes Dependabot PR #27).
- `lizard` 1.24.1 → 1.24.3 in all lint/test images.
- Fedora 46: `ca-certificates-2026.2.92_v9.0.319`, `python3-3.15.2`.
- Rocky 9: `ca-certificates-2026.2.92_v9.0.319`.
- Ubuntu 26.04: `ca-certificates=20260816ubuntu0.26.04.1*`.
- CI: `SonarSource/sonarqube-scan-action` v8.3.0 → v8.4.0 (SHA-pinned).

## Validation

- `./scripts/build-and-test.sh --full` (Docker lint, coverage gate, distro matrix compat + e2e).

## Breaking Changes

None. Installs whose mail user is not a plain email address now keep the placeholder recipient
instead of having it injected.

## Upgrade Notes

No manual intervention is required. Existing installations update automatically via the scheduled
`update_self.sh` routine or via `install.sh --update`.
