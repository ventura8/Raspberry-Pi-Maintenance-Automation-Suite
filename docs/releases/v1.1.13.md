# v1.1.13: Prevent Gmail app password leakage to temporary files and argv

## Summary

A security audit identified that `wt_passwordbox` used `_wt_capture`, which created a user-owned
temporary file under `/tmp` to capture dialog output via `--output-fd 3` before reading it with `cat`
and unlinking it. On multi-user systems or environments with unprivileged local processes watching `/tmp`,
the credential could be read during the window between write and unlink. In addition, `configure_email_text`
and `configure_email_whiptail` stripped spaces using `echo "$app_pass" | tr` pipelines, and text UI
`read_input` passed inputs through `xargs`, exposing the cleartext password in process arguments (`/proc/<pid>/cmdline`).

This release closes both exposure vectors: whiptail captures dialog output in-memory directly over file
descriptor 3 without creating any filesystem paths, and secrets are sanitized strictly using pure Bash
parameter expansion with zero subprocesses.

## What Changed

### 1. In-memory dialog output capture for whiptail

- `_wt_capture` no longer invokes `mktemp` or writes dialog results to `/tmp`. Whiptail output on
  `--output-fd 3` is duplicated directly to stdout (`3>&1`) within subshell execution, streaming
  the password or selection straight into Bash variable memory across an anonymous kernel pipe.
- When wizard UI file descriptors are active, UI rendering and terminal control remain strictly tied to
  `/dev/tty` (`INSTALL_UI_OUT_FD` / `INSTALL_UI_IN_FD`) while descriptor 3 connects to the parent
  process capture pipe.

### 2. Secret input sanitation via bash parameter expansion

- `read_input` now checks `is_secret == "true"`: secret variables bypass the external `xargs` pipeline
  and are sanitized in pure Bash (`${user_val//$'\r'/}` and parameter pattern trimming), preventing
  cleartext secrets from appearing in `/proc/*/cmdline`.
- `configure_email_text` and `configure_email_whiptail` replace `echo "$app_pass" | tr` pipelines with
  pure Bash parameter expansions (`${app_pass//$'\r'/}` and `${app_pass//[[:space:]]/}`).

### 3. Automated regression tests

- Added BATS regression tests in `tests/install_whiptail.bats` confirming that `wt_passwordbox` does not
  invoke `mktemp` or touch temporary files, and `read_input` with secret mode does not invoke `xargs`.

## Upgrade Notes

No manual intervention is required. Existing installations will update automatically via the scheduled
`update_self.sh` routine or via `install.sh --update`.
