# v1.1.11: Stop reporting "failed to query" when fwupd firmware is up to date

## Summary

On hosts without a Raspberry Pi (fwupd path), the firmware report said
"fwupdmgr failed to query update availability" even when every device was current. fwupd exits
with code `2` (`FWUPD_EXIT_CODE_NOTHING_TO_DO`) when there is nothing to upgrade, and the
script counted any non-zero exit as a failed query. Exit code `2` now means "No updates available."

## What Changed

- `update_pi_firmware.sh` reads the exit code of `fwupdmgr get-upgrades`. Exit `0` or `2` counts as
  a successful query. Any other code still falls back to `get-updates`, then reports
  "failed to query".
- The update-detection rule is unchanged: a `New version:` / `Release ID:` block means an update is
  available.
- New BATS test in `tests/component_tests.bats` replays the real up-to-date output with exit `2`.
  It checks that the script reports "No updates available.", does not fall back, and does not
  install or reboot.
- `docs/script_logic.md` documents the exit-code rule.
