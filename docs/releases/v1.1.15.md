# v1.1.15: Pin mail config paths so the environment cannot redirect them

## Summary

Follow-up hardening to v1.1.14. `install.sh` still honoured `MSMTP_CONF` / `SSMTP_CONF` / `REVALIASES`
from the environment when `TEST_MODE=true`. Because `TEST_MODE` is itself an environment variable,
same-UID malware could still choose which mail config `download_scripts` reads (redirecting root-cron
reports to a valid attacker address) and where `save_email_configuration` writes the Gmail app
password via `sudo tee`. This release pins the paths unconditionally.

## What Changed

### 1. Fixed mail config paths (`install.sh`)

- `MSMTP_CONF`, `SSMTP_CONF` and `REVALIASES` are always `/etc/msmtprc`, `/etc/ssmtp/ssmtp.conf` and
  `/etc/ssmtp/revaliases`; no environment override is honoured, with or without `TEST_MODE`.
- `lib/mail_send.sh` keeps its `${VAR:-default}` defaults (used only by root-cron maintenance scripts);
  `install.sh` sets the paths before sourcing it.

### 2. Test isolation moved into the harness

- New test-only `tests/helpers/install_test_paths.sh` sources `install.sh` and then points the paths at
  the mocks (or runs `install_main` when executed). Production runs never go through it.
- BATS installer tests, `scripts/matrix_install_flow.sh`, `scripts/run_e2e.sh`,
  `scripts/run_distro_compat_smoke.sh` and the kcov drivers use the helper.
- `tests/install_extended.bats` asserts the paths ignore the environment with and without `TEST_MODE=true`.

## Validation

- `./scripts/build-and-test.sh --full`: Docker lint, coverage gate (≥ 90% overall and per file),
  distro matrix compat + e2e on all five lanes.

## Breaking Changes

None for installs. Contributors overriding mail paths in tests must use the harness helper.

## Upgrade Notes

No manual intervention is required. Existing installations update automatically via the scheduled
`update_self.sh` routine or via `install.sh --update`.
