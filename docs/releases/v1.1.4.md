# v1.1.4: use the real fwupdmgr flag (--no-reboot-check) and report install failures

## Summary

v1.1.3 fixed `fwupdmgr` update *detection*, which exposed the next problem in the same code path:
the install step ran `fwupdmgr update -y --no-reboot`, and `--no-reboot` is not a real fwupd flag.
fwupd 2.x (2.1.1 observed on an ASUS NUC) rejects it with
`Failed to parse arguments: Unknown option --no-reboot`, so the pending UEFI dbx release was still
not installed — and because the script did not check the exit status, the report ended with the
benign "No firmware update was applied or no reboot is required." The correct flag is
`--no-reboot-check` ("Do not check or prompt for reboot after update"), accepted by fwupd 1.x and
2.x. The same wrong flag was in the Samsung SSD LVFS path. Test mocks previously accepted any
argument, so neither call site was covered; they now reject unknown options like real fwupd.

## What Changed

### 1. `fwupdmgr update` invocation

- `update_pi_firmware.sh` and `update_samsung_ssd.sh` now call
  `fwupdmgr update -y --no-reboot-check`.
- The exit status of `fwupdmgr update` is captured. On failure the report prints
  `ERROR: 'fwupdmgr update' failed (exit code N). Firmware was NOT updated.` and no reboot is
  scheduled, instead of silently falling through to the "no update applied" footer.

Files:

- `scripts/update_pi_firmware.sh`
- `scripts/update_samsung_ssd.sh`
- `README.md`, `docs/script_logic.md`

### 2. Tests

- The shared `fwupdmgr` mock (`tests/setup_mocks.sh`) and the real-output replay mock in
  `tests/component_tests.bats` now fail `update` with
  `Failed to parse arguments: Unknown option …` for any option that real fwupd does not accept —
  so a wrong flag fails CI. Both "installs" regressions fail against v1.1.3 and pass here.
- New `Component: Firmware - fwupdmgr update failure is reported and does not reboot`.
- New Samsung tests: `LVFS Update Available installs with fwupd 2.x-compatible flags` (the LVFS
  install path had no positive-case coverage before) and
  `LVFS update failure is reported and does not reboot`.

Files:

- `tests/setup_mocks.sh`
- `tests/component_tests.bats`
- `tests/component_tests_samsung.bats`

## Validation

- `./scripts/build-and-test.sh --full` — lint-in-docker, coverage gate, and the full distro matrix.
- Flag verified against `fwupdmgr update --help` on fwupd 2.1.1 (`--no-reboot-check` present,
  `--no-reboot` absent).

## Breaking Changes

- None.

## Notes

- Hosts pick this up on the weekly `update_self.sh` run (Sunday 01:00 by default); the firmware
  run at 02:00 the same night will then install any release fwupd had been reporting, and reboot
  if the update requires it.
