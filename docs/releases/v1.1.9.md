# v1.1.9: Close same-UID library swaps in the installer bootstrap and lib install

## Summary

A security scan found that malware running as the installing user could swap the installer's
helper libraries. A swapped `pkg_install` could hijack the first `sudo` prompt during
`curl | bash`. A swapped checkout library could be copied into the root-owned suite tree, which
root cron runs. This release closes both paths.

## What Changed

### 1. In-memory bootstrap (`curl | bash`)

- `_fetch_bootstrap_libs` downloads `ui_msg.sh`, `os_pkg.sh`, and `mail_send.sh` and `eval`s them
  in memory. They are no longer written to a user-owned `mktemp -d` and then `source`d.
- A failed `ui_msg.sh` download stops the bootstrap instead of continuing.
- `lib/os_pkg.sh` and `lib/mail_send.sh` skip their `BASH_SOURCE`-relative `ui_msg.sh` lookup
  when the helpers are already loaded. A planted `./ui_msg.sh` in the current directory is never
  sourced.

### 2. Trusted local libraries only

- New `_install_src_trusted`: when the install needs root, `download_scripts` copies a local
  `lib/` file only if the file, its directory, and every ancestor are owned by root and not
  writable by group or others. Sticky ancestors above the parent (such as `/tmp`) are allowed.
- The copy uses the validated canonical path, so a user-owned symlink cannot be retargeted after
  the check.
- Libraries in user-owned checkouts or staging trees are streamed from `$RAW_URL` through
  `sudo install /dev/stdin` instead.

### 3. Tests and docs

- 6 new BATS tests in `tests/install_root_owned.bats` cover the in-memory bootstrap, the
  fail-closed `ui_msg.sh` fetch, the planted cwd `ui_msg.sh`, user-owned ancestors, symlink
  canonicalization, and streaming of untrusted checkout libraries.
- `AGENTS.md`, `docs/script_logic.md`, and the installer-tester skill describe the new rules.

## Upgrade Notes

No action is needed. Existing installs pick this up through the weekly `update_self.sh` run.
