# v1.1.10: Fail closed on every install path when helper libraries are missing

## Summary

A follow-up to v1.1.9. If the `curl | bash` bootstrap could not load the helper libraries, only
`--update` stopped. Fresh and interactive installs carried on configuring email and downloading
scripts without `pkg_install` / `has_mail_sender`. Every install path now stops instead.

## What Changed

- `install_main` calls `_ensure_install_helpers` before the matrix, fresh, and existing-install
  paths, not only before `--update`. When the helpers are missing it exits with status 1 and
  never creates `$INSTALL_DIR`.
- The error message is now "Error: package helpers not loaded. Cannot continue."
- A new BATS test in `tests/install_root_owned.bats` makes every library download fail and
  checks that a fresh install exits 1 without creating the install directory.
- `AGENTS.md` describes the rule.

## Upgrade Notes

No action is needed. Existing installs pick this up through the weekly `update_self.sh` run.
