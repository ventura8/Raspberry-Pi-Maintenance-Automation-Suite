# v1.1.8: SonarQube Cloud coverage import and a clean issue list

## Summary

SonarQube Cloud has never shown coverage for this project. The project ran on Automatic
Analysis, which cannot import coverage reports, and the CI `sonarqube` job skipped without a
`SONAR_TOKEN`. Sonar also has no native Bash coverage importer. This release converts the
kcov coverage gate's output into Sonar's generic coverage format, and the CI scan now imports it.
It also fixes all 21 open SonarQube Cloud issues (20 code smells and 1 vulnerability).

## What Changed

### 1. Coverage on SonarQube Cloud

- `tests/transform_coverage.py` also writes `coverage/sonar-coverage.xml` (Sonar generic
  coverage format) next to the merged `coverage/cobertura.xml`. Only files that exist in the
  repo are included.
- `sonar-project.properties` sets `sonar.coverageReportPaths=coverage/sonar-coverage.xml` and
  excludes `tests/**` from main sources (they are already indexed as test code).
- The `sonarqube` job in `.github/workflows/ci.yml` now `needs: coverage-gate`. It downloads the
  `coverage-gate` artifact, fails if the report is missing, and then scans.

### 2. SonarQube Cloud issues

- `docker:S6471`: the lint image now runs as a non-root user (`USER 10001`), and
  `scripts/lint-in-docker.sh` runs the container as the host uid/gid with `HOME=/tmp`.
- `shelldre:S7682` (explicit `return`): the single-line `_pi_gettext` / `_pi_echo` fallback stubs
  in `install.sh`, `uninstall.sh`, `lib/os_pkg.sh`, and `lib/mail_send.sh` are now full functions
  that end with `return`, matching `lib/ui_msg.sh`. The same fix applies to the `is_installed`
  stubs in `scripts/coverage/kcov_install_driver.sh`.
- `shelldre:S7679` (positional parameters): `$1` is now assigned to a named local in
  `_retire_legacy_install_dirs`, `_msmtp_resolve_default_field`, `_msmtp_default_field`, and the
  kcov driver stubs.
- `shelldre:S1481`: `get_current_email_user` now checks the msmtp host it resolves instead of
  leaving an unused `hub` variable.
- `shelldre:S7688`: the image-build helper `docker/images/tests/scripts/common.sh` and
  `scripts/run_docker_matrix.sh` now use `[[` instead of `test` / `[`.
- `shelldre:S7684`: `_with_path` in `scripts/coverage/kcov_lib_driver.sh` scopes `PATH` with a
  prefix assignment instead of an uppercase `local PATH`.

## Validation

- `./scripts/build-and-test.sh --lints-only` passed (shellcheck, shfmt, bash -n, yamllint,
  actionlint, hadolint, mdformat), with the lint image running as non-root.
- `./scripts/build-and-test.sh --full` passed: Docker lint, the coverage gate on `debian:trixie`
  (91.76% overall, every file at or above 90%, complexity 12), and compat + e2e on every distro
  lane. The gate wrote `coverage/sonar-coverage.xml` for all 9 covered product files.

## Breaking Changes

- None for installed hosts.

## Notes

- Maintainer action required for coverage to appear: add the `SONAR_TOKEN` repository secret, and
  turn off Automatic Analysis in the SonarQube Cloud project (Administration → Analysis Method).
  Until then the `sonarqube` job skips, and Automatic Analysis keeps running without coverage.
